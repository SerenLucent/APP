# TwoPlace

Android APK와 iPhone 웹을 함께 사용하는 커플 앱입니다. 웹 화면은 Vite, Android 패키징은 Capacitor, 커플방 서버는 Node.js + SQLite로 구성합니다. Node.js 22.13 이상이 필요합니다.

## 실행

```sh
npm install
npm run dev
```

http://localhost:5173 에서 웹과 방 API를 함께 실행합니다. 첫 화면의 ‘커플 등록하기’를 누르면 숫자 12자리 방 코드가 생성됩니다. 상대는 ‘커플방 입장하기’에서 그 코드를 입력합니다. 같은 Wi-Fi의 다른 기기에서는 PC의 LAN 주소와 5173 포트로 접속할 수 있으며 방화벽의 접속 허용이 필요할 수 있습니다. localhost는 각 기기 자신을 가리킵니다.

## 동작

- 최초 화면: 커플 등록하기 | 커플방 입장하기
- 입장 후 좌측 상단: 디데이 설정·수정. 시작일을 1일로 계산합니다.
- 입장 후 우측 상단: 숫자 12자리 방 코드, 누르면 복사. 클립보드를 사용할 수 없는 환경에서는 수동 복사 입력란을 엽니다.
- 코드 입력 시 생성자의 방으로 입장하며, 한 방의 입장은 두 기기까지 허용합니다.
- 디데이·캘린더·메모는 서버에 저장하고 약 3초 간격으로 공유합니다. 입력창이 열려 있으면 자동 갱신을 미루고, 동시 수정 충돌은 최신 내용을 읽은 뒤 다시 저장하도록 안내합니다.
- 새로고침해도 같은 기기·브라우저의 입장을 유지합니다. 별도 로그인/기기 교체/입장 복구는 아직 없습니다. 브라우저 저장소 삭제 시 입장 정보를 잃으며, 이미 두 기기가 등록된 방에는 코드만으로 새 기기를 추가할 수 없습니다.
- 플레이스메이트는 연동 준비 안내입니다. 외부 앱의 주소/API가 정해지면 연결합니다.

기존 v1 기기 내 데이터는 삭제하지 않습니다. 새 커플방에는 자동으로 옮기지 않으며, 현재 화면은 서버의 방 데이터를 사용합니다. 방 코드는 초대 수단이므로 상대에게만 전달해 주세요.

## 서버 배포

정적 파일만 올리는 방식으로는 커플방이 동작하지 않습니다. Node 서버를 함께 실행해야 합니다.

```sh
npm run build
npm start
```

기본 포트는 3000이며 PORT 환경변수로 바꿀 수 있습니다. 서버는 dist의 웹 파일과 /api를 함께 제공합니다. 공개 사용 시 HTTPS 주소로 배포하고 SQLite 파일을 영구 디스크에 보관하세요. ROOM_DB_PATH로 DB 경로를 지정할 수 있으며 기본값은 .data/rooms.sqlite입니다. 단일 서버 프로세스 기준입니다. 별도 웹 도메인에서 API에 접근하면 ALLOWED_ORIGINS에 정확한 출처를 쉼표로 구분해 지정하세요. 프록시 뒤의 IP별 입장 시도 제한은 현재 프록시 주소를 기준으로 계산합니다.

iPhone은 HTTPS 주소를 Safari로 연 다음 ‘홈 화면에 추가’할 수 있습니다. 오프라인 저장은 아직 지원하지 않습니다.

## Android

APK와 웹이 같은 서버를 사용하도록 .env.local에 실제 API 주소를 지정한 후 다시 빌드합니다.

```text
VITE_API_URL=https://your-server.example
```

```sh
npm run android:sync
npm run android:open
```

Android Studio에서 APK를 만들거나 android 폴더에서 ./gradlew.bat assembleDebug를 실행합니다. 개발용 결과는 android/app/build/outputs/apk/debug/app-debug.apk입니다. 배포용 서명은 별도입니다. VITE_API_URL은 빌드 시 반영되며 기존 방의 기기 입장 정보는 API 서버에 종속됩니다.

**아직 공개 서버를 배포하지 않았습니다. 현재 제공하는 APK는 화면 확인용 빌드로, 서버 주소 미설정 시 등록·입장이 불가능하다는 안내를 표시합니다.** APK 설치만으로 휴대폰 두 대가 인터넷에서 연결되는 상태는 아닙니다.

## 파일

- releases/TwoPlace-debug.apk: 변경된 화면을 반영한 개발용 APK. 공용 API 주소 미설정.
- releases/TwoPlace-web.zip: dist 웹 파일 + server 서버 소스 + 실행 안내. 압축을 풀고 Node 22.13 이상에서 npm start로 실행합니다. 서버는 Node 내장 모듈만 사용하므로 이 배포 묶음의 실행에는 npm install이 필요하지 않습니다.
- docs/welcome-preview.png: 최초 등록·입장 화면
- docs/room-preview.png: 입장 후 디데이와 방 코드 화면

## 검증

npm test로 독립 클라이언트의 생성·입장·공유, 방 격리, 잘못된 코드, 세 번째 기기 차단, 권한 확인, 동시 수정 충돌, 서버 재시작 후 유지, 네트워크 재시도 시 중복 방지까지 검사합니다. 웹 빌드 및 Android assembleDebug 빌드에 성공했습니다. 브라우저에서 390px 레이아웃, 잘못된 코드 안내, 생성·입장·복사·새로고침 유지도 확인했습니다. 실제 Galaxy/iPhone 검증과 공개 HTTPS 배포는 남아 있습니다.

이전에 보고된 Capacitor CLI의 iOS 빌드 하위 의존성 xcode → uuid 관련 moderate 취약점 3건은 npm audit fix로 해결되지 않았습니다. 웹 런타임에 포함되는 의존성은 아니며 CLI 업데이트 시 재확인이 필요합니다. AST 화면 자료는 제공되지 않아 요청한 배치를 기준으로 디자인했습니다.

## 캘린더 카테고리와 상세 일정

날짜를 테두리가 있는 네모 칸으로 표시하며, 일정은 최대 3개까지 짧게 표시합니다. 더 많으면 +N개로 표시하고 날짜 팝업에서 전체를 볼 수 있습니다. 긴 일정 이름은 칸 안에서만 줄여 보이고 팝업과 상세보기에서는 전체 이름을 보여 줍니다.

- 일: 퇴근 / 휴무 선택. 퇴근은 시간 필수이며 19:00은 ‘퇴근 19’, 19:30은 ‘퇴근 19:30’으로 표시합니다. 휴무는 시간 없이 등록합니다.
- 여행: 여행 이름과 계획을 기록합니다. 이름을 비우면 ‘여행’으로 표시합니다. 지역 선택은 플레이스메이트 연동 시 구현할 예정이며 현재는 넣지 않았습니다.
- 데이트: 데이트 이름, 선택 시간, 갈 곳, 계획을 미리 적을 수 있습니다. 이름을 비우면 ‘데이트’로 표시합니다.
- 일반: 자유롭게 제목과 계획을 적습니다. 기존에 만든 일정도 유지됩니다.

날짜 선택 → 일정 목록 팝업 → 일정 상세보기에서 장소와 계획을 읽거나 수정·삭제할 수 있습니다. 같은 방의 서버 데이터로 공유하며 공개 서버 미배포 상태에 대한 제한은 위 설명과 같습니다. 최신 검증은 총 6개 테스트가 통과했으며 분류·시간·장소·계획의 양방향 공유와 기존 형식 호환을 포함합니다. 390px 브라우저에서 네 가지 분류 등록, 팝업, 상세보기와 수정 시 값 유지를 확인했습니다. 예시 데이터는 별도 calendar-preview.sqlite 테스트 DB에만 저장했습니다.

미리보기: docs/calendar-preview.png, docs/calendar-day-popup.png

## 모찌와 쿠키의 집

홈의 ‘펫 키우기’ 메뉴 또는 하단 메뉴로 들어갑니다. 모찌와 쿠키 두 마리를 함께 키우며 앞마당·테라스·집 안 세 공간을 볼 수 있습니다. 캐릭터를 누르면 쓰다듬기 반응을 보이고, 돌보기에서 캐릭터별 먹이 주기·쓰다듬기·잠깐 쉬기를 선택합니다. 현재 이동은 CSS로 만든 기본 연출로, 방향별 스프라이트나 장애물 충돌 처리는 아직 없습니다.

- 시작 하트 120개, 먹이 4개를 방당 한 번 지급합니다.
- 서버 시간 기준 시간당 10하트가 쌓이며, 버튼으로 수령합니다. 최대 24시간분까지 적립하고 남은 분 단위 시간은 유지합니다. 한 시간 전에는 수령하지 못합니다.
- 먹이는 10하트이며 한 마리의 배부름을 25 채웁니다. 배부름은 시간당 4씩 줄고 0 아래로 내려가지 않습니다. 이미 배부르면 먹이를 소모하지 않습니다.
- 상점에서 방석·화분·테이블·러그·조명·울타리를 하트로 구매합니다. 가구 40개, 먹이 100개까지 보관합니다.
- 꾸미기에서 가구를 선택한 다음 공간을 눌러 자유롭게 배치합니다. 키보드용 배치 위치 버튼도 제공합니다. 배치한 가구는 다시 이동하거나 보관할 수 있습니다.
- 하트·먹이·배부름·소유 가구·배치는 서버에 저장하여 둘이 공유합니다. 펫 게임 저장소를 일정·메모와 분리해 두어, 캘린더 변경으로 잔액이나 가구가 덮어써지지 않습니다. 동시 동작에는 버전 충돌 검사를 적용합니다.
- 돌아다니는 위치, 현재 보고 있는 공간, 쓰다듬기·먹기·쉬기 애니메이션은 각 기기의 화면 연출입니다. 두 기기의 펫 위치를 프레임 단위로 동기화하지 않습니다.

내장 image_gen으로 캐릭터 기준표를 참고해 투명 PNG를 만들었으며 최종 파일과 생성 프롬프트는 docs/pet-assets.md에 기록했습니다. 현재 캐릭터당 기본 전신 1장을 사용하며, 추후 방향별 원화와 모션을 추가할 수 있습니다. 공개 HTTPS 서버와 APK API 주소 설정은 여전히 필요합니다.

총 10개 테스트로 기존 기능과 하트 시간 경계·적립 상한·중복 수령·잔액 부족·먹이 소모·소유권·동시 구매·공유·서버 재시작 후 저장을 검사합니다. 테스트 예시는 별도 pets-preview.sqlite에만 저장했습니다.

## 캐릭터 서 있는 모습 v2

모찌와 쿠키를 짧은 다리로 서 있는 투명 PNG로 교체했습니다. 쿠키 귀의 별과 꼬리 중간의 작은 별은 없앴고 꼬리 끝의 큰 별은 유지합니다. 등록 화면·프로필·펫 공간에 모두 새 파일을 연결하고 발끝 기준 점프와 그림자 애니메이션을 조정했습니다. 기존 앉은 PNG는 보관만 합니다. 현재 파일과 내장 image_gen 수정 프롬프트는 docs/pet-assets.md를 참고하세요.

## 방향별 캐릭터와 입체 꾸미기 v3

모찌와 쿠키의 옆·뒷모습 투명 PNG를 추가했습니다. 정면은 기존 v2를 사용하고 옆모습을 반전해 좌우 이동에 사용합니다. 화면상 이동 방향에 따라 정면·옆면·뒷면을 고르며, 짧은 다리로 통통 뛰는 CSS 모션을 유지합니다. 각 방향 파일과 실제 생성 프롬프트는 docs/pet-directions-v3.md에 있습니다. 이동 원화는 방향별 기본 자세이며 프레임별 다리 스프라이트는 아닙니다.

앞마당·테라스·집 안을 바닥 높이와 벽 면이 보이는 2.5D 공간으로 바꿨습니다. 가구도 같은 시점에서 그립니다. 바닥은 8×8 좌표로 다루며 배치 모드에서 초록색은 가능, 붉은색은 겹침·공간 초과로 불가능한 자리입니다. 회전 버튼으로 가구 방향을 바꿔 배치할 수 있고, 러그 위에는 다른 가구를 놓을 수 있습니다. 서버에서도 소유권·겹침·영역·회전 입력을 검증합니다.

펫은 가구가 차지한 바닥 칸을 피해서 경로를 찾습니다. 친구를 고른 다음 바닥을 누르면 해당 친구가 그쪽으로 이동합니다. 앞마당의 집이 차지하는 뒤쪽 자리에는 펫과 새 가구가 들어가지 않습니다. 펫끼리의 충돌과 프레임 단위 네트워크 위치 동기화는 구현하지 않았습니다.

기존 가구의 좌표와 잔액은 유지하고 화면에 투영하는 방식만 바꿨습니다. 이전 방식으로 겹쳐 놓은 가구는 자동으로 옮기지 않으며 다음 배치부터 새 규칙을 적용합니다. 기존 각도의 미리보기 PNG는 이전 버전 기록이며 v3는 docs/pets-isometric-v3-preview.png를 참고하세요.

서버 실행에는 shared/pet-space.js가 필요합니다. 배포 묶음에 dist, server, shared를 모두 포함해야 합니다. 정적 웹만 올려서는 방 공유 기능이 동작하지 않는 점과 APK API 주소 설정 필요 조건은 이전과 같습니다.

## 펫 선택과 목적지 표시

캐릭터 또는 돌보기 프로필을 누르면 한 마리가 선택됩니다. 선택한 캐릭터는 투명 PNG 외곽을 따라 노란 네온빛이 생기며 이름표도 노란색으로 표시합니다. 선택 상태에서는 자동 산책을 멈추고 바닥을 누른 목적지로 이동합니다. 목적지 바닥 한 칸은 약 1.2초 동안 깜빡인 후 제거됩니다. 선택하지 않은 상태에서는 바닥을 눌러도 이동 명령을 보내지 않습니다.

바닥 안을 누를 때는 선택을 유지하고, 가구·바닥 밖 배경·메뉴·다른 영역을 누르면 테두리를 해제합니다. 먹이 주기·쓰다듬기 등 돌보기 동작은 마지막으로 고른 친구를 대상으로 합니다. 쓰다듬기 반응은 별도 돌보기 버튼으로 사용할 수 있습니다. 화면 효과와 선택은 해당 기기에만 적용하며 하트나 공유 저장 데이터는 바꾸지 않습니다.

브라우저에서 단독 선택, 다른 영역 선택 해제, 바닥 칸 생성 및 자동 제거, 이동 후 선택 유지, 가구 클릭 해제를 확인했습니다. 동작을 줄이는 설정에서는 점멸 대신 짧은 사라짐 효과를 사용합니다.

### 거실과 각자의 방
- 앞마당의 현관을 누르면 거실에 들어갑니다. 테라스 탭은 제거했습니다.
- 거실에는 고정 소파와 싱크대·쿡탑·수납장이 있고, 모모네방과 쿠키네방 문으로 각 방에 들어갑니다.
- 방은 기존 실내 배경을 사용하며, 모든 공간에서 두 펫의 이동과 별도 가구 배치를 지원합니다.

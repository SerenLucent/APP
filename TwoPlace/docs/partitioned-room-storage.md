# 분리 저장 구조 (storageVersion 2)

커플 폴더 아래에 다음 파일을 둡니다. 기존 원본은 `backups/storage-v2_커밋.json`으로 남깁니다.

```
room.json                           연결·복구·멤버, revision, 문서 목록과 건수
wallet/current.json                 하트·먹이·돌보기, 최신 version
housing/layout.json                 구입/보관/배치한 물건, 벽지·바닥
adventure/profile.json              별조각·물약·스탯·스킬·누적 클리어·최근 게임
calendar/calendar_2026.json         해당 연도 일정 + 중복 보상 방지 장부
notes/notes.json                    커플 메모
heart-history/2026/11/heart_2026_11_10.json
game-history/2026/11/clear_2026_11_10.json
```

이력은 한국 시간으로 매월 1일부터 3일씩 묶고, 월말은 말일까지 포함합니다.
빈 기간은 생성하지 않으며 원본에 남아 있는 이력을 모두 이전합니다. 과거 버전에서 이미
삭제된 하트 이력은 복원하지 않습니다. 게임 이력의 룰렛 칸 배열은 중복 저장하지 않고 결과만 보존합니다.

## 읽기

- 일반 `/room`: 기본 정보 + 작은 재화/돌보기 파일만 읽습니다.
- `/room/content`: `housing`, `notes`, `calendar`(years), `adventure` 중 요청 항목만 읽습니다.
- `/room/history`: 종류, 시작일, 종료일(최대 31일)을 받아 필요한 3일 파일만 합칩니다.
- 게임 이력은 처음에 최근 31일, ‘이전 기록 더 보기’로 앞선 31일씩 조회합니다.
- 조회 중에는 이전 데이터를 읽고 있다는 메시지, 실패하면 오류와 재시도를 표시합니다.
- 펫 키우기는 모모·쿠키 로딩 화면에서 배치 데이터와 캐릭터/가구 이미지를 준비한 뒤 표시합니다.

## 저장과 무결성

GAS는 Git Data API의 tree/commit/ref를 사용해 변경된 문서와 재화·이력을 한 커밋으로 게시합니다.
다른 작업이 먼저 브랜치를 갱신하면 강제 덮어쓰기 없이 409를 반환합니다. 실패한 저장의 부분 반영은 없습니다.
읽기는 하나의 커밋에 고정해 서로 다른 시점의 문서를 섞지 않습니다.
SQL 서버는 같은 논리 파일 경로를 `room_documents` 테이블에 저장하고 트랜잭션으로 처리합니다.

수정하지 않은 캘린더 연도와 다른 기능의 파일은 덮어쓰지 않습니다. 달력 보상 장부도 연도별로
보존해 중복 지급을 막습니다. 게임 요청 중복 방지 ID는 기존대로 최근 128개를 유지하며, 완료한
게임은 최근 run의 완료 표시로도 중복 보상을 막습니다.

클라이언트는 GAS에 `storageProtocol:2`, Node API에 `X-TwoPlace-Storage: 2`를 보냅니다.
분리된 방에 구버전 클라이언트가 쓰기를 시도하면 최신 버전으로 다시 열도록 안내합니다.
GAS 관리자의 구형 전체 덮어쓰기는 차단합니다. 재화/이력 없이 잘못 덮어쓰지 않기 위한 처리입니다.

## 이전과 배포

`node scripts/partition-room-data.mjs`는 원격의 고정 커밋을 읽어 `.data/storage-v2`에
변환본과 백업을 만듭니다. 원격 파일은 수정하지 않습니다.
실제 서버에서는 새 프로토콜로 최초 접근할 때 원본 백업과 모든 분리 파일을 한 번에 생성합니다.
처음 한 번은 변환에 시간이 걸릴 수 있으며, 배포 시 웹과 GAS를 함께 갱신해야 합니다.

배포 대상은 GAS v25와 같은 변경의 웹 클라이언트입니다. 기존 방은 첫 접속 시 원본 백업을 남기고 자동 분리됩니다. 로컬 변환본을 실제 방 데이터 위에 직접 덮어쓰지 않습니다.
